
# 한국어 답변

**반드시** 한국어로 답변

# 들여쓰기

- 들여쓰기는 **반드시** 공백(` `)으로 작성

# 주석 규칙

- 코드를 그대로 해석하는 What 무엇, How 방법에 대한 주석을 **절대** 작성하지 않음
    - 예를 들어, `int a = 1; // a에 1을 할당` 금지
- 코드를 모두 이해하더라도, 이해할 수 없는 Why 이유나 이면의 의미하는 바를 주석으로 작성

# 텍스트 제한

텍스트 작성할 때, 허용되는 문자는 아스키 8~9, 32~126번 문자, 한글 전체, 이모지만 가능하고, 다른 문자는 제한

# 규칙 문서

- 항상 읽히는 규칙은 `rules/`, 작업할 때 골라 읽는 규칙은 `skills/`에 있음
- 규칙에 적히지 않은 주제는 규칙이 없는 것이므로 임의로 정하지 않고 사용자에게 물어봄

| 문서                              | 언제 읽는가                                                              |
| --------------------------------- | ------------------------------------------------------------------------ |
| `rules/project-folder.md`         | 모노리포 폴더 구조, 읽거나 고치면 안 되는 폴더                           |
| `rules/architecture.md`           | 백엔드 패키지, 4계층, 의존 방향                                          |
| `rules/how-to-run.md`             | 백엔드 실행, 컴파일, 테스트, 빌드 명령                                   |
| `rules/infra.md`                  | 서버 구성, CI/CD, 배포 경로                                              |
| `rules/network.md`                | 서버 네트워크 보안 경계                                                  |
| `rules/conventional-commits.md`   | 커밋 메시지 작성                                                         |
| `skills/backend-convention`       | RestController, Dto, 서비스, 엔티티, Repository, 예외, 검증, 설정을 만들거나 고칠 때 |
| `skills/test-code`                | 테스트 코드를 작성하거나 실행할 때                                       |
