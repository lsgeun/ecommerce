# 프로젝트 구조 파악 지침

## 기본 원칙

- 프로젝트의 전체/부분 구조나 파일 위치, 기술 스택 등 프로젝트의 핵심 요약을 파악해야 하는 상황에서는 항상 `@docs/project-directory.md`를 **가장 먼저 참조**한다.

## 탐색 순서 (Workflow)

1. **1단계 (문서 우선 확인):** 프로젝트 탐색 관련 툴(Find, Grep, LS 등)을 사용하기 전, `@docs/project-directory.md` 내용을 먼저 확인하여 위치와 역할을 파악한다.
2. **2단계 (툴을 통한 보완):** 문서 내용만으로 정보가 부족하거나, 실제 최신 코드베이스 구조 확인이 추가로 필요한 경우에만 툴을 사용하여 탐색을 진행한다.

# 프로젝트 구조 변경

- 임의로 프로젝트 구조 `@docs/project-directory.md`를 바꾸면 절대 안되고, 반드시 사용자의 승낙을 받은 후에 바꿔야 한다.
- 사용자가 `update-project-directory-docs` 스킬을 명시적으로 요청한 경우에만 이 파일을 바꿔야 한다.
