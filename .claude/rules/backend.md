# `backend/**/src/main/java/`

## 패키지 폴더 구조

1. `기본 패키지`는 `io.github.lsgeun.ecommerce`
2. `기본 패키지` 바로 아래에 **반드시** `도메인 패키지`(`product/`, `user/`, `notification/` 등), `공용 패키지`(`common/`)만 둔다.
3. 도메인 패키지 바로 아래 **반드시** 4개의 패키지(`표현 계층` `presentation/`, `응용 계층` `application/`, `도메인 계층` `domain/`, `인프라 계층` `infrastructure/`)만 둔다

화살표는 `import`하는 방향

```
presentation -> application -> domain <- infrastructure
```

## `공용 패키지`

`공용 패키지`에는 모든 도메인에서 사용되거나 백엔드 설정을 하는 등 백엔드 전반에 공통적으로 적용되는 폴더, 파일을 둔다.

`기본 패키지` 아래에 `도메인 패키지`에 들어가지 않는 모든 폴더, 파일이 `공용 패키지`에 들어간다.

예를 들면, 예외 처리, 공용 엔티티, cors 방지를 한 웹 설정 등

### 의존

`도메인 패키지`의 모든 파일은 `공용 패키지`에 의존할 수 있다.

## `도메인 계층`

### 의존

`도메인 계층`에 있는 파일들은 **절대** `표현 계층`, `응용 계층`, `인프라 계층`에 의존하지 않는다.

`도메인 계층`에서 도메인은 기본적으로 엔티티와 합쳐진 형태이므로, 엔티티 관련 라이브러리에 의존할 수 있다. 예를 들면, Jakarta Persistence 인터페이스, Spring Data JPA 라이브러리 등.
다만, 필요에 따라, 도메인과 엔티티가 분리되어야 하는 경우, 도메인과 엔티티는 분리될 수 있고, 이 경우 도메인은 엔티티 관련 라이브러리에 의존할 수 없다.

## `인프라 계층`

### 의존

`인프라 계층`은 **절대** `표현 계층`, `응용 계층`에 의존하지 않는다.

## `응용 계층`

### 의존

`응용 계층`은 **절대** `표현 계층`, `인프라 계층`에 의존하지 않는다.

## `표현 계층`

### 의존

`표현 계층`은 **절대** `도메인 계층`, `인프라 계층`에 의존하지 않는다.
다만 `표현 계층`에서 dto와 도메인을 서로 변환해주는 매퍼에서만, 변환의 목적으로만, 도메인을 의존할 수 있다.
